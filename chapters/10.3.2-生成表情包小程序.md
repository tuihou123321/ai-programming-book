## 10.3.2 AI表情包微信小程序开发实战指南

**项目简介：** 本章用腾讯 CodeBuddy 搭配阿里云百炼的通义千问图生图模型，带你一步步完成“AI表情包”微信小程序。我们把每个环节都交给 AI 领路：先让它问出你遗漏的需求，再请它生成页面、云函数和配置说明。用户只需上传头像、选择想要的表情，系统就能生成统一风格的贴纸图并保存到手机。完成效果如图图10.3.2.1、图10.3.2.2所示

### 10.3.2.1 本文核心知识点

1. **AI 驱动的开发流程**：用自然语言和 CodeBuddy 协作，完成从需求梳理到代码导入的全流程。
2. **通义千问图生图接入方法**：理解接口调用、鉴权和结果处理方式。
3. **微信云开发资源的实际用途**：为什么需要云存储、云函数、云数据库，以及它们分别解决什么问题。
4. **API 概念速通**：API 就像服务台窗口，你按格式提问，服务台按约定返回答案，本项目通过 API 向通义千问索取图片。
5. **上线与调试要点**：体验版、审核、发布的关键动作与常见注意事项。

> 小科普：当你调用通义千问图生图时，发送的就是一份 API 请求。它包含“我要处理的图片在哪里”“希望变成什么表情”等信息，阿里云收到后按规则生成图片并把结果返回给你。

### 10.3.2.3 第一步：提示词优化与需求梳理

既然是用 AI 编程，就让 AI 提前搞清楚我们想做什么。你只需回答它的追问，就能避免知识盲区遗漏。

**提示词示例：**

```text
请你以“面向零基础学员的资深 AI 小程序产品教练”身份回答，语气耐心、步骤清晰，使用通俗语言。

请按照以下格式输出：
1. 需要我补充或确认的问题。
2. 分步骤方案：说明 AI 自动完成的事项，并用 `[人工执行]` 标出需要我亲自操作的动作。
3. 可直接粘贴到 CodeBuddy 的结构化提示词。

项目简介：我想开发一个“AI表情包”微信小程序。
核心流程：
- 用户上传人物、动物或卡通头像；
- 选择 9 种表情中的一个（开心、大笑、哭泣、生气、惊讶、疑惑、害羞、得意、无语）；
- 调用阿里云通义千问图生图模型生成一张透明背景、风格统一的表情贴纸；
- 支持保存到手机。

核心说明：项目的云端能力全部使用微信云开发 CloudBase，实现云存储（上传原图与生成图）和云函数（安全调用通义千问 API）；当前版本不做历史记录页面。

请协助完成：
1. 梳理完整需求：页面布局与交互、云存储用途（如何把本地图片转换为可访问的网络地址）、云函数职责（隐藏通义 API Key 并封装调用）、通义千问接口所需的参数与鉴权方式、安全与费用提醒，以及由于目前只能获得临时 HTTPS 链接而暂不接入云数据库的处理方案与未来扩展建议。
```

**对话要点：**

- 当 AI 询问图片规格时，明确说明：输出为 512×512 的透明 PNG，无水印。
- 如果它问到是否批量生成，确认当前版本一次只生成一张，用户点击一次就出结果。

### 10.3.2.4 第二步：申请通义千问图生图能力

1. 在阿里云百炼控制台启用 `qwen-image-edit` 模型，复制 API Key。
2. 记下接口地址：`https://dashscope.aliyuncs.com/api/v1/services/aigc/multimodal-generation/generation`，调用时需在请求头中加入 `Authorization: Bearer <API Key>`。
3. 入参重点：原图的可访问 URL、描述用的文本提示（例如“保留角色特征，表情为开心大笑，透明背景”）、是否去除水印。
4. 响应会返回 OSS 临时链接；云函数需要把它再保存回微信云存储，方便前端下载。

> 调试建议：先用 curl 或 Postman 跑通一次请求，确认提示语能生成正确表情，再交给小程序调用，能省去大量排错时间。



### 10.3.2.5 第三步：让 CodeBuddy 生成小程序框架

1. 把整理好的提示词贴到 CodeBuddy，对话中保持“让 AI 引导你”的习惯：如果它说还缺少某个字段，就补充信息；如果它问你要不要新增页面，就结合需求决定。

1. 让 CodeBuddy 输出：
   - 小程序的页面结构（如 `pages/upload`, `pages/result` 等）。
   - 上传图片、选择表情、点击生成、展示结果、保存到手机的交互逻辑。
   - 调用云函数的示例代码和文件目录。
2. 根据 AI 生成的说明，把项目下载或复制到本地目录，准备导入微信开发者工具。

> 如果页面不够友好，继续提示 CodeBuddy：“请加一步一步的引导文案”“请增加失败重试按钮”。让 AI 直接改代码，效率最高。

### 10.3.2.6 第四步：云存储——把临时图片变成可用 URL

- **为什么需要云存储？** 小程序里图片初始只存在用户手机本地，通义千问接口却要求网络地址。把文件上传到云存储，就能得到临时 URL。
- 操作步骤：在云开发控制台创建 `emoji-inputs` 和 `emoji-outputs` 文件夹；前端用 `wx.cloud.uploadFile` 上传图片，拿到云文件 ID；再用 `cloud.getTempFileURL` 换取临时 HTTPS 链接给通义千问使用。
- 生成的图片同样需要上传到 `emoji-outputs`，方便后续下载与记录。

> 如果调用接口时提示图片不可访问，先检查云存储权限是否开放，或者临时 URL 是否已过期。

### 10.3.2.7 第五步：云函数——安全封装通义 API

- **为什么需要云函数？** 通义的 API Key 一旦放在前端就会暴露，任何人都能调用。云函数让密钥留在服务器端，并统一处理请求、错误和日志。
- 在 `cloudfunctions/generateEmoji` 中实现流程：
  1. 接收前端传来的表情类型和图片临时链接。
  2. 拼接对应的提示语（如“请生成一个惊讶表情”）。
  3. 调用通义千问接口，带上 `Authorization` 头和请求体。
  4. 解析返回的图片链接，下载后再上传到云存储。
  5. 返回新的云文件 ID 给前端，方便展示和保存。
- 别忘了设置超时时间、错误提示以及日志输出，问题一目了然。
- 在微信开发者工具里勾选云函数并上传部署。

### 10.3.2.8 第六步：暂不启用云数据库（原因说明）

- **为什么没有接入云数据库？** 微信云存储返回的图片地址都是临时 HTTPS 链接，过期后就无法再次访问。如果想把这些链接存成长期记录，需要先准备备案过的自有域名，再把云存储的文件绑定为固定地址。对于学习版本来说，这一步成本较高且流程复杂。
- **当前做法**：生成的图片只保存在云存储中，用户在当次生成后即可下载；后台不额外记录历史，避免出现临时链接失效、管理员打开却看不到图片的问题。
- **后续扩展建议**：当你有备案域名、能把云存储绑定成固定 URL 时，再接入云数据库记录历史数据。届时可重新参考 CodeBuddy 生成插入记录的云函数逻辑。

### 10.3.2.9 第七步：联调、测试与体验优化

- **功能测试**：逐一点击 9 种表情，确认生成结果与描述一致。
- **体验提示**：生成过程中显示进度或加载动画，失败时提供重试与常见原因说明。
- **安全与费用**：提醒用户上传合规图片；在云函数里做好失败兜底，避免无限重试耗尽配额。
- **和 AI 配合检查**：遇到 bug 时，请 AI 阅读日志并给出修复建议，让它带着你排查。

### 10.3.2.10 发布与分享

1. **上传代码**：在微信开发者工具中点击“上传”，填写版本号与更新说明。
2. **设为体验版自测**：登录公众平台 → “开发管理” → “版本管理”，把最新版本设为体验版，和同事或朋友一起验证生成、保存等功能。
3. **提交审核**：
   - 类目可选“工具-AI/智能体”或“娱乐-图片”。
   - 功能描述示例：“基于通义千问 AI，上传头像选择表情即可生成微信贴纸。”
   - 如果未来加了登录或付费功能，记得提供测试账号。
4. **发布上线**：审核通过后在“待发布”页面手动点击“发布”，“AI表情包”小程序即可对所有用户开放。
