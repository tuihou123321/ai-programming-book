## 10.2.2 智能 Chrome 扩展开发实操指南

**项目简介：** 本指南沿用上一节的工作流，演示如何借助 OpenAI Codex 和 VS Code，从零开始构建一款能够即时翻译网页内容的 Chrome 浏览器扩展。我们会以自然语言驱动 Codex 完成代码生成，接入智谱 AI 的通用翻译模型，在浏览器侧栏展示实时翻译结果，帮助读者把多语言网页快速变成可读中文（或其他目标语种）。流程覆盖需求澄清、代码生成、导入调试、配置密钥和迭代优化，适合想用 AI 快速交付功能型插件的读者。

### 10.2.2.1 本文核心知识点

　　在动手之前，先明确通过本节可以学到的核心能力。

1. **理解翻译插件的结构**：拆解 popup、后台脚本、内容脚本、侧栏 UI 的分工，掌握信息流走向。
2. **利用 Codex 高效生成代码**：用对话方式描述功能，交由 Codex 输出 Manifest、UI、脚本与通信逻辑。
3. **对接智谱 AI 翻译能力**：学习如何配置 API Key、调用翻译接口、处理多语种与错误状态。

### 10.2.2.2 开发准备：Chrome 与 OpenAI Codex

　　智能翻译扩展依旧基于 Chrome Manifest V3，先确保本地环境就绪。

- **开启浏览器开发者模式**：在地址栏访问 `chrome://extensions`（Edge 用户访问 `edge://extensions`），打开右上角“开发者模式”，后续才能加载未打包扩展、查看日志。
- **VS Code + Codex 插件**：安装最新版 VS Code，在扩展市场搜索“OpenAI Codex”，登录账号后即可在侧栏与 Codex 对话、生成或修改文件。

**注意：** 推荐在桌面创建单独目录（例如 `smart-translate-extension`），用 VS Code 打开该目录并确认 Codex 面板可用，再继续后续步骤。

1. **明确翻译场景与交互**

提示词如下：

```text

请基于以下需求编写一个 Chrome 浏览器扩展：

1. 自动扫描与翻译：在用户访问任意网页时，content script 自动扫描可见的英文文本节点，调用智谱 AI 模型 API 将其翻译成中文。
2. 内容处理：
   - 仅翻译用户可见内容，忽略脚本、样式、隐藏元素等非展示文本；
   - 对动态加载的内容也应生效（可使用 MutationObserver）。
3. 页面展示：保留原页面结构，翻译后默认展示中文，同时保存原文以便恢复，支持原文/译文切换。
4. 功能控制：在扩展的 popup 页面添加一个按钮或开关，允许用户启用或禁用翻译功能，并显示当前状态。
5. 配置项：将智谱 AI 的 API Key 作为插件配置项，在 popup 页面中提供配置和保存功能。
6. 技术与性能：
   - 使用 Manifest V3；
   - 组织代码为 background service worker、content script、popup UI，并提供清晰的模块划分；
   - 处理调用失败或网络异常时的错误提示，避免页面卡顿；
   - 可考虑简单的缓存策略减少重复请求。
7. 交付物：请给出完整的项目文件结构及源码，并说明如何在本地加载调试该扩展。

```

### 10.2.2.5 第三步：导入插件到浏览器

　　生成代码后，即可在 Chrome 或 Edge 中加载体验。

1. **加载未打包扩展**
   - 打开 `chrome://extensions` 页面，确认“开发者模式”已开启。
   - 单击“加载已解压的扩展”，选择 `smart-translate-extension` 目录。
   - 如果结构正确，扩展会马上出现在列表中（如图10.2.2.5 所示）。

### 10.2.2.7 第五步：插件测试阶段

　　配置完成后，开始在不同网页上测试翻译效果。

- **功能验证**：在英文、日文等网页中打开扩展，观察侧栏是否正确显示原文、目标语言及翻译文本，如图10.2.2.9 ，10.2.2.10 所示。
- **多模式测试**：切换“一段一译”和“整页翻译”模式，确认加载动画、错误提示是否按预期显示。
- **稳定性检查**：在长页面、动态加载页面（如社交媒体流）测试，留意内容脚本是否能捕获新增段落。
